# pyegeria 6.2.37 (draft)

pyegeria 6.2.37 adds standard-document output to report specs and corrects how report specs render text.

## New

- **DOCUMENT output type (SD-1).** A report spec can produce one standard document instead of rendered columns:
  `exec_report_spec(name, output_format="DOCUMENT", params=...)` returns
  `{kind: "document", standard, media_type, file_name, text, validation, notes}`. `validation` is always present
  (`valid`, `invalid` or `not_validated` with the reason), and `notes` says what the document leaves out and why.
  Validators are registered by name (`register_document_validators`); `json-schema` and `shacl` are built in and
  never fetch over the network. `run_report --output-format DOCUMENT --output <dir> [--force]` writes the file.
  See "Document outputs" in `docs/output-formats-and-report-specs.md`.
- **DCAT Catalog (SD-2).** The built-in specs "DCAT Catalog" (JSON-LD) and "DCAT Catalog (Turtle)" export the
  Assets in a collection as a DCAT-AP 3 catalog, read as the caller, validated against the DCAT-AP 3.0.1 SHACL
  shapes shipped with pyegeria (CC BY 4.0). DigitalProducts and Agreements are Bitol's and are named in the notes,
  never exported.
- **Structured TABLE (R1).** `exec_report_spec(..., output_format="TABLE", table_shape="structured")` returns
  `kind: "table"`: columns with an inferred type and render, rows of native values keyed by column, `total`/
  `shown`, and `notes` for every cap or reduction. The default is unchanged.
- **Native DICT (R1).** `dict_shape="native"` on `exec_report_spec` / `generate_output` (and the async twin)
  returns DICT rows with native values: lists, related elements with both names, classifications and zones as
  lists. The default `"flat"` is unchanged.
- **Dependencies:** rdflib, pyshacl and jsonschema are now plain dependencies (about 2.25 MB of wheels: pyshacl
  1.31 MB, rdflib 0.62 MB, pyparsing, html5rdf, owlrl, prettytable). The pyegeria wheel grows by about 56 KB.

## Behaviour change: rendered text changes on upgrade

The report-spec fix-now corrections change rendered **text** (REPORT, LIST, MD, FORM, HTML and the CLI table).
**DICT and JSON shapes are unchanged**, except that a DICT/TABLE result that filled its page now also carries a
top-level `notes` list beside `data`. Anything that parses pyegeria's rendered text should be re-checked.

- **F1:** header classifications are joined with `", "` (no stray newline before the comma).
- **F2:** REPORT/MD/FORM show a `False` or `0` value instead of dropping it.
- **F3:** FORM/MD say "Diagram omitted in this format; see REPORT or MERMAID." where a diagram was silently
  dropped (the camelCase `solutionBlueprintMermaidGraph` now matches too); `links`, `implemented by` and
  `sub_components` render as values.
- **F4:** the CLI table shows list items with "(+N more)" instead of "N items", and a map as one `k: v; ...`
  cell instead of dotted columns.
- **F5:** the CLI table keeps the author's column order and names the columns it cannot show
  ("+N more columns: ...") instead of dropping them silently.
- **F6:** LIST no longer drops an unnamed object in a list value: it shows its first text value or
  "(unnamed <type>)".
- **F7:** the Digital-Products `Members` column is filled (Egeria's field is `collectionMembers`; it was empty on
  every row). Relationship columns still show qualifiedNames by default.
- **F8:** a result that filled its page says so: "Showing the first 100: the query stopped at its page size of
  100; more may exist." in `notes` and in the text. `page_size`/`start_from` given as text are converted to whole
  numbers, and anything else is refused in words.
- **F9:** markdown table cells escape `|` and turn newlines into `<br>`; markdown emphasis is kept.
- **F10:** `format="bulleted-list"` works in REPORT/MD (a markdown list), not only in LIST.
