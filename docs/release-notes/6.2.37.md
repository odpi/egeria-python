# pyegeria 6.2.37

pyegeria 6.2.37 adds standard-document output to report specs (a DCAT-AP 3 catalog of Assets first), and corrects
and extends how report specs render complex values:
- **New output, new shapes, all opt-in:** a DOCUMENT output type with validators; a structured TABLE
  (`table_shape="structured"`) and native DICT rows (`dict_shape="native"`); per-column render intents.
- **Existing applications work unchanged:** the same calls return the same result shapes. Structured and native
  results come back only when a caller asks for them, and DICT stays flat by default.
- **Behaviour change:** rendered **text** changes on upgrade (see below). Anything that parses pyegeria's rendered
  text (REPORT, LIST, MD, FORM, HTML or the CLI table), rather than DICT or JSON, should be re-checked.

## New

- **DOCUMENT output type (SD-1).** A report spec can produce one standard document instead of rendered columns:
  `exec_report_spec(name, output_format="DOCUMENT", params=...)` returns
  `{kind: "document", standard, media_type, file_name, text, validation, notes}`.
  - `validation` is always present: `valid`, `invalid`, or `not_validated` with the reason. A validator that fails
    is `not_validated` with its error type and line/column, never its parser's text.
  - `notes` says what the document leaves out and why.
  - Validators are registered by name (`register_document_validators`); `json-schema`, `shacl` and
    `dcat-ap-3-shacl` are built in. A validator never fetches over the network, and a report spec may name only
    `package:` files (a spec can be held in Egeria and written by any user).
  - `run_report --output-format DOCUMENT --output <dir> [--force]` writes the file and prints the validation line.
  - See "Document outputs" in `docs/output-formats-and-report-specs.md`.
- **DCAT Catalog (SD-2).** The built-in specs "DCAT Catalog" (JSON-LD) and "DCAT Catalog (Turtle)" export the
  Assets in a collection (`scope`, a qualifiedName or GUID) as a DCAT-AP 3 catalog, read as the caller and
  validated against the DCAT-AP 3.0.1 SHACL shapes shipped with pyegeria (CC BY 4.0; source and hashes in
  `pyegeria/view/data/dcat-ap-3/README.md`).
  - DigitalProducts and Agreements are Bitol's: each is named in the notes, never exported.
  - A zoned Asset the caller can read is `dct:accessRights NON_PUBLIC`; a member Egeria refuses with a 403 is noted
    as "not visible", never as absent.
  - Every property left out says why in the notes.
- **Structured TABLE (R1).** `exec_report_spec(..., output_format="TABLE", table_shape="structured")` (and the
  async `_async_run_report`) returns `kind: "table"`:
  - `columns`, each with an inferred `type` (scalar, text, list, map, elements, table) and a `render`;
  - `rows` of native values keyed by column key, related elements as `{guid, qualifiedName, displayName, type}`;
  - `total`, `shown`, `total_basis` ("one page") and `notes` for every cap or reduction;
  - an empty relationship cell is "none" when the relationship was read, and "not read" when it was not
    requested;
  - a table shows two levels: a third is reduced to a count and names, with a note.
- **Native DICT (R1).** `dict_shape="native"` on `exec_report_spec`, `generate_output` and the async twin returns
  DICT rows with native values: lists stay lists, related elements carry both names, classifications and zones are
  lists, and `format=True` columns are not stringified. The default `"flat"` is unchanged; TABLE stays flat under
  `dict_shape`. Any other `table_shape` or `dict_shape` value is refused in words.
- **Column render intents (R2).** A report-spec column can set `render` (text, join, bullets, kv, subtable, count,
  link), `max_items` (default 10), `max_lines` (default 3) and `label` (`qualified_name`, the default, or
  `display_name` for related elements in text outputs). All four are carried in Egeria-held specs (`label` as
  `related_label` in a microflow column item).
- **The CLI draws the structured table (R3).** `run_report --output-format TABLE` renders with Rich: lists one
  item per line, maps as nested tables, long text cut at `max_lines` with "…", each sub-table as a separate table
  after the main one, and dropped columns named in a footer. `list_generic` keeps flat rows unless asked.
- **My Egeria and the report TUI read native DICT (R4).**
  - Shop for Data's catalog, root-collection and domain details ask for `dict_shape="native"` and read related
    elements as lists (`value_names`). The Domains tree no longer shows one leaf per character of a joined string,
    and a link-wrapped "Containing Members" value is unwrapped.
  - The report TUI (`my_reports`) shows a list as one joined cell (+N more past 10) and a dict as JSON in one
    cell, instead of turning list items or dict keys into extra columns.
  - The Data Products demo no longer splits a value that can be a list.

## Fixed

- **Digital-Products `Members` was empty on every row** (F7). Egeria returns a collection's members as
  `collectionMembers`; the spec's `members` column now reads it when the element has no `members` field.
- **A capped result said nothing** (F8). Digital-Products returned exactly 100 of 445 products with no word. A
  result that fills its page now says so, as `notes` beside `data` and as a line in text output:
  "Showing the first 100: the query stopped at its page size of 100; more may exist." The record of what each
  list request sent is kept per call, so concurrent runs on one shared client never mix their notes.
- **`page_size` / `start_from` given as text** are converted to whole numbers; anything else is refused in words
  instead of reaching Egeria.

## Behaviour change: rendered text changes on upgrade

These corrections change rendered **text** (REPORT, LIST, MD, FORM, HTML and the CLI table). **DICT and JSON row
shapes are unchanged**; a DICT/TABLE result that filled its page also carries a top-level `notes` list beside
`data`.

- **F1:** header classifications are joined with `", "` (no stray newline before the comma).
- **F2:** REPORT/MD/FORM show a `False` or `0` value instead of dropping it.
- **F3:** FORM/MD say "Diagram omitted in this format; see REPORT or MERMAID." where a diagram was silently dropped
  (the camelCase `solutionBlueprintMermaidGraph` now matches too); `links`, `implemented by` and `sub_components`
  render as values.
- **F4:** the CLI table shows list items with "(+N more)" instead of "N items", and a map as one `k: v; ...` cell
  instead of dotted columns.
- **F5:** the CLI table keeps the author's column order and names the columns it cannot show
  ("+N more columns: ...") instead of dropping them silently.
- **F6:** LIST no longer drops an unnamed object in a list value: it shows its first text value or
  "(unnamed <type>)".
- **F7:** the Digital-Products `Members` column is filled. Relationship columns still show qualifiedNames by
  default.
- **F8:** capped results say so (above).
- **F9:** markdown table cells escape `|` and turn newlines into `<br>`; markdown emphasis is kept.
- **F10:** `format="bulleted-list"` works in REPORT/MD (a markdown list), not only in LIST.
- **R2, Digital-Products:** its Product Manager and License columns show the related element's display name (for
  example "Data for Internal Use" instead of "LicenseType::Jacquard::LICENSE-TYPE-IOU::Data for Internal Use") in
  every output of that spec (DICT, TABLE, LIST, REPORT, FORM). This is the spec's own `label: display_name`; no
  other spec or column changes.
- **R3, LIST cells:** a list of scalars renders as bullets (`a<br>b`) instead of "a, b"; a related-element list
  past `max_items` (10) shows "(+N more: ...)", and a map shows `k: v<br>...`. Columns with `format=True` or a
  `detail_spec` render as before.

## Dependencies and size

- rdflib, pyshacl and jsonschema are now plain dependencies (about 2.25 MB of wheels: pyshacl 1.31 MB, rdflib
  0.62 MB, pyparsing 0.13 MB, html5rdf 0.11 MB, owlrl 0.06 MB, prettytable 0.04 MB; jsonschema was already
  installed).
- The pyegeria wheel is 3,366,371 bytes, 76,742 bytes (about 75 KB) more than 6.2.36's 3,289,629. The DCAT-AP 3.0.1
  shapes account for most of it.
