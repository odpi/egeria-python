# pyegeria 6.3.4

pyegeria 6.3.4 adds **solution boundaries** (odpi/egeria #9465): pyegeria methods, report specs and the Dr.Egeria
commands Create Solution Boundary and Create Design Model Boundary. It also fixes how Dr.Egeria updates a boundary,
and makes the refused `Status: DRAFT` message point to Content Status.

```bash
pip install -U pyegeria
```

**Needs an Egeria platform with odpi/egeria#9465 (6.4-SNAPSHOT 5a8d6a12 or later) for the boundary features. On 6.3
the boundary calls return 404.** Everything else works as in 6.3.3.

Checked for this release:
- the 3.13 micro-tests;
- the Dr.Egeria round-trip probe on a scratch Egeria at 5a8d6a12, with a new baseline `5a8d6a12.json`;
- a live check of the boundary features on that scratch platform, which found the Dr.Egeria defect fixed below.

## New

- **Solution boundaries in `SolutionArchitect`.**
  - Methods: `create_solution_boundary`, `create_solution_boundary_from_template`, `update_solution_boundary`,
    `delete_solution_boundary`, `find_solution_boundaries`, `get_solution_boundary_by_guid` and
    `get_solution_boundaries_by_name`, each as a sync and an `_async_` pair.
  - Members are added and removed with the Collection Manager's member calls, as for blueprints.
  - `generate_solution_boundary_output` formats the results.
- **Property classes** `SolutionBoundaryProperties` and `DesignModelBoundaryProperties` in `pyegeria.models`. They are
  collections and add no property of their own.
- **Report specs `Solution-Boundary` and `Solution-Boundary-Mermaid`.**
  - A **Member Hierarchy** column lists a boundary's members, with nested boundaries as indented lines, both levels.
    It stops, and says so, at 8 levels or 500 lines.
  - `Solution-Boundary` is the default `report_spec` of the boundary finds.
- **Dr.Egeria: Create Solution Boundary and Create Design Model Boundary** (Solution Architect family), with Basic and
  Advanced templates and report specs.
  - Members are added with the existing Collection Membership command.
  - A Design Model Boundary is created, read and updated through the collection requests; the view service has no
    boundary request for it. Its find also returns solution boundaries, because a solution boundary is a design model
    boundary.
- The generated Properties catalog now comes from Egeria 2e22b1e85b, which knows both boundary classes.

## Fixes

- **Dr.Egeria: a boundary command never changes, or creates, the other kind of boundary.**
  - An Update (or a Create that found an existing element) aimed at an element of the other boundary type is refused,
    with a message that names both types and the GUID. Nothing is written.
  - An `Update Solution Boundary` or `Update Design Model Boundary` with an explicit GUID either updates that element
    or is refused. Before, aiming `Update Solution Boundary` at a Design Model Boundary's GUID created a new Solution
    Boundary: the boundary read found nothing, the lookup fell back to the name, and the Update became a Create. Now
    the element is read by GUID and the command is refused if it is the other type, missing or unreadable.
  - Commands without a GUID, and all other commands, look up as before.
- **Dr.Egeria: `Status: DRAFT` points to Content Status.**
  - Since 6.3.3 (PY-68), the `Status` that Dr.Egeria adds to 12 commands is checked against Egeria's element
    statuses, so `Status: DRAFT` is refused.
  - On Create Schema Type, Schema Attribute, Display Data Container and Display Data Field, the error now ends:
    "'Status' here is the element status; to set DRAFT, use 'Content Status' instead". Write `Content Status: DRAFT`.
  - Create Rating, Create Like and the six glossary Classify/Declassify commands have no content status, so DRAFT has
    no place there.
- **Dr.Egeria: Create Solution Role no longer offers Title and Role Domain Identifier.** Egeria stores neither for a
  solution role, so the templates no longer show them. They are still accepted if given, and reported as not stored.

## Known issues

- **Update <X> by Display Name only can create a duplicate when Create added a Version Identifier; give the Version
  Identifier or the GUID (#613).**
  - Create fills in the default Version Identifier (1.0) and puts it in the qualified name. Update does not, so an
    Update that names only the Display Name can miss the element and be turned into a Create.
  - This affects most Create commands that have a qualified-name prefix. It is not new in 6.3.4.

## Also in this release

- Round-trip probe (`scripts/dr_egeria_roundtrip_probe`):
  - a baseline for Egeria 5a8d6a12;
  - it sends DRAFT as Content Status where Status is the element status;
  - the Project Scope known gap is removed, now that it matches.
- CI: `ossf/scorecard-action` 2.6.0 (#608).
