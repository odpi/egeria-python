# pyegeria 6.2.39

pyegeria 6.2.39 fixes how Dr.Egeria reads list attributes.

## Fixed

- **A bullet containing a comma was split into two items.** Dr.Egeria split every list attribute's value (`Simple
  List`, `List`, `NameList`, `Reference Name List`, in both the v2 parser and the older md_processing path) on
  commas, semicolons and newlines. A bullet such as "Results go to the Service Owner and the depending domain, not
  only to IT" became two items. The CDO workbook's IT governance metric "Recovery Test Coverage" was stored with 6
  implications instead of 4.
  - Now a bulleted or multi-line value is one item per bullet (or line), verbatim, with the leading `- `, `* ` or
    `+ ` removed.
  - A single-line value is still split on commas and semicolons ("a, b" is two items), including an inline
    bulleted list on one line ("- a; - b, c" is three).
  - **Behaviour change:** a single bullet on its own line, such as "- a, b", is now one item (it used to be two).
  - Spec metadata (labels, valid values) is parsed as before.

**Correcting stored data:** re-run the affected Dr.Egeria documents. An Update (or a Create that becomes an Update)
sends the whole list with `mergeUpdate: true`, and Egeria's merge update replaces a property's value as a whole, so
the list is replaced, not appended. A list attribute left out of the document is not changed.
