# pyegeria 6.2.27

## Changed

- **A capped count is "not measured" (#555).** A count that fails, times out, or whose find
  fallback stopped at its 500-element page cap (a lower bound, not a total) is now `None` with a
  note, where before it could be `0` or the cap itself ("Total Cataloged Assets = 500").
  `exec_report_spec` puts the notes on the output as `unmeasured`
  (`[{"count", "reason", "at_least"}, ...]`); a scalar count that was not measured, and a
  `SERIES`/`BAR`/`PIE` over one, come back as `kind: "absent"` with the reason and the lower bound
  in `content`. Measured results are unchanged. A `viewer` count with `strict=False` still returns `0` when the query itself fails; pass `strict=True` for `None`. See
  [Counts: not measured, and whose population](../output-formats-and-report-specs.md#counts-not-measured-and-whose-population).
- **Totals count the whole repository by default (#556).** The count routines (`count_elements`,
  `count_elements_by_property`, `count_relationships`, `counts_by_type`, `people_counts`,
  `usage_context_counts`, `feedback_summary`, `business_value_signals`, `growth_series`) default to
  `population="repository"`, which includes elements the viewer may not be able to see, as a
  deliberate interim choice until zone-aware push-down exists. `population="viewer"` is an
  explicit opt-in. `scope=` is a deprecated alias of `population=`. A failed repository count is
  `None` with a note, never `0`. `feedback_summary` and `count_relationships` now declare
  `egeria_client:EgeriaTech`.

## Egeria 6.3 (#558)

- `NotificationType.notificationInterval` is gone in Egeria 6.3. pyegeria no longer sends it;
  Dr.Egeria's `Notification Interval` attribute is removed, and the subscription attribute is now
  `Minimum Notification Interval` (minutes; the old label still parses). For a subscription
  request pyegeria sends both `notificationInterval` and `minimumNotificationInterval` for now,
  because a platform reads only its own name.
