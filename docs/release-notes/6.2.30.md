# pyegeria 6.2.30

## Changed

- **Dr.Egeria: Zone Membership is now a Basic attribute.** Every command that takes it (126 commands:
  the Create commands built on the shared `New-Element` bundle, `Link Notification Subscriber`, and
  `Classify`/`Reclassify Zone Membership`) shows it in the Basic templates as well as the Advanced ones.
  Its default is empty: the template shows the heading with no value, and no zone is added for you.
  - The Basic `*-DrE-Basic` report specs for those commands gain a *Zone Membership* column, as the
    Advanced ones already had (123 generated specs; the seed is regenerated).

## Fixed

- **A blank Zone Membership no longer clears an element's zones.** A Zone Membership heading with no
  value parses to an empty list, and Create/Update then cleared the element's ZoneMembership
  classification. Now an empty or absent Zone Membership sets no zones and leaves existing zones as they
  are; only a value sets them. To remove zones, use `Declassify Zone Membership`. For
  `Link Notification Subscriber`, an empty Zone Membership is sent as no value rather than an empty list.
- **The Zone Membership column shows the zones, not the classification object.** Egeria v6 returns an
  element's zones as an `ElementClassification` at `elementHeader.zoneMembership`, so a report column
  `zone_membership` showed the whole object as text. It now shows the zones as one string
  (`"a, b"`), or nothing when the element is in no zone. This fixes the `*-DrE-Advanced` specs, which
  already had the column, and the `*-DrE-Basic` specs that gain it in this release. The header
  properties (`_extract_referenceable_properties`) now include `zone_membership` as that string too.
