# pyegeria 6.2.29

## Changed

- **Built-in report specs ship as packaged JSON: the seed (RS-EGERIA-TIER stage 2).**
  - The registry's `builtin` tier now loads from `pyegeria/view/seed/`: one JSON file per family (38) plus
    `manifest.json`. It loads once per process, through `seed_report_specs()`. Before, it was built from the Python
    constants.
  - Each spec gives exactly the output it gave in 6.2.28. All 437 load equal to their 6.2.28 definitions, and the
    census is unchanged: 437 specs, 376 runnable, 0 unrunnable, 61 format-only.
  - The constants (`base_report_specs`, `generated_format_sets`, the analytic demos and the question specs) stay
    only as the generator's input:
    - `python -m pyegeria.view.seed build` writes the seed, and `refresh_specs` now runs it.
    - `python -m pyegeria.view.seed check` fails when the seed is stale.
  - A seed file that fails to load is skipped with a warning naming it, and the rest still load.
- **The analytic demo specs and `Questions`, `Report-Types` and `Question-Specs` are now `builtin`, not `local`.**
  - They ship in the seed. `list_report_specs(with_status=True)` reports `source: "builtin"` for them, and a run's
    `spec_source.tier` is `builtin`.
  - pyegeria no longer declares its own `analytic_demos` entry point in the `pyegeria.report_specs` group, and the
    question specs are no longer registered into the RUNTIME tier at import.
  - **If you installed pyegeria from a checkout (editable), reinstall it so the removed `analytic_demos` entry point
    drops out of the installed metadata** (`uv sync`, or `pip install -e .`). Until then a refresh loads the demos a
    second time as local specs, and they shadow the seed's identical copies with a warning each.
- **A local spec now overrides a built-in of the same label: local > egeria > builtin.**
  - "Local" means a file in the user report specs directory, an installed package's entry point, or
    `register_report_specs()`.
  - Before, such a spec was skipped (`refresh_report_specs()` listed it) or refused (`ReportFormatCollision`).
  - It now wins, with one warning per label per process, worded as for an Egeria-held copy: `Report spec
    '<label>': the local copy shadows the builtin copy (...); the builtin copy stays addressable as
    'builtin:<label>'.`
  - `builtin:<label>` (or `seed:<label>`) and `egeria:<label>` still reach the shadowed copy.
  - An alias of a local spec that a built-in or Egeria-held spec already holds is dropped from the local copy, with
    one warning.
  - Two local sources still may not share a label.
  - With no local specs, the registry is exactly the seed.
- **`spec_source` for a built-in spec names its seed file**, for example `{"tier": "builtin", "label":
  "Search-Keywords", "version": None, "seed": "Feedback Manager.json"}`.
- **microflow/1 additions**, for specs held in Egeria. An older pyegeria refuses a spec that uses them.
  - A format-only spec has `"stages": []`, no `params` and at least one formatter.
  - A find stage's `additional_props` names the per-element hook (`FormatSet.get_additional_props`). Only the
    functions on `ADDITIONAL_PROPS_HOOKS` are allowed.
  - A formatter's `same_as` shares an earlier output format's formatter, as a `Format` with several types does.
