# pyegeria 6.2.38

pyegeria 6.2.38 fixes two bugs found in the 6.2.37 live check.

## Fixed

- **The "DCAT Catalog" spec could not run a search-scoped catalog** (F-DCAT1, new in 6.2.37). Its file name was
  `{scope}-dcat.jsonld`, so a run with `search_string` instead of `scope` was refused with "needs parameter 'scope'"
  before the exporter ran. A DOCUMENT file-name field can now name alternatives, `{scope|search_string}`: the first
  parameter the run supplies is used, made file-name safe as before. Both built-in specs ("DCAT Catalog" and
  "DCAT Catalog (Turtle)") use it; a run with neither parameter is refused with "needs one of the parameters
  'scope', 'search_string'".
- **My Egeria: selecting a business domain showed "No business domain data returned for GUID: ['BusinessCapability',
  '…']"** (F-ME1). The domain tree stores `[type name, GUID]` on each node and the whole list was passed as the GUID.
  The selection screen now passes the GUID; a leaf that stores nothing (domain members, glossary folder terms,
  root-collection folders) passes its qualified-name label instead of `None`.
