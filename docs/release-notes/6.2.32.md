# pyegeria 6.2.32

## Changed

- **One copy of the generated report specs as Python code, kept current.** pyegeria shipped three
  copies of `dr_egeria_reports.py` (`pyegeria/`, `pyegeria/config/` and `pyegeria/view/`), last
  generated before 6.2.28 and nothing in pyegeria imports them. The two orphan copies and the
  `pyegeria/config/` package are removed. `pyegeria/view/dr_egeria_reports.py` is regenerated (304 sets,
  the same as `md_processing/data/generated_format_sets.json`; the old file had 150), and
  `refresh_specs` now regenerates it on every run, so it cannot drift again. `gen_report_specs --emit
  code` writes there by default. If you imported `pyegeria.dr_egeria_reports` or
  `pyegeria.config.dr_egeria_reports`, import `pyegeria.view.dr_egeria_reports` instead.
