# pyegeria 6.2.26

Report specs and analytic routines (RS Wave 2, part 3). The user-facing description is in
[Routines, declarations and roles](../output-formats-and-report-specs.md#routines-declarations-and-roles)
and [Will this spec run?](../output-formats-and-report-specs.md#will-this-spec-run-load-time-resolution).

Context: 6.2.25 added routine declarations (`RoutineDeclaration`, `ParamDeclaration.category`,
`Binding`, `TileSafety`, `Admission`; #546) and load-time resolution of every report spec
(`spec_resolver`, checks 1-7; `list_report_specs(with_status=True)`; #548).

## Added

- **Inputs by role (#552).** A routine declares its non-JSON arguments as `inputs`:
  `egeria_client:<Class>`, `reader:<name>`, `viewer`, `subject`. The executor asks a
  `RoleSupply` for each one before the routine's first stage runs and binds them to the leading
  positional arguments in declared order; declared `params` follow by name. No parameter name is
  read to decide what to pass.
- **`exec_report_spec(..., supply=)`** takes an environment's own supply. Without one, plain
  pyegeria's `PlainSupply` supplies the caller's `EgeriaTech` (for `EgeriaTech` and every class it
  proxies to) and nothing else: no readers, no viewer, no subject. A find-method spec ignores
  `supply`.
- **`RoleRefused`, `NoSuchReader`, `CallerTokenExpired`** (`pyegeria.view.role_supply`), all
  `ValueError`s, raised before any stage runs, with the environment's words.
- **Check 5** (declared inputs against the python binding's leading client arguments) is shared
  by the resolver and the executor, so its words are the same at load and at run.

## Changed (compatibility)

- A routine registered from outside pyegeria (CONFIG JSON, an installed entry point, or at
  runtime) whose function takes leading client arguments (`mgr`, `ce`, `expert`, `client`) but
  declares no `inputs` is refused from 6.2.26. Before, it was bound by argument name.
  **Fix: declare its inputs.** The built-in routines all declare theirs.

## Removed

- **`analytic_binders` (#553).** The binder is gone. For one release a spec that still carries the
  key loads and the key is ignored: silently when empty, with a `DeprecationWarning` and a
  logged warning when not. Declare the argument as a `reader:<name>` input instead and have the
  environment's supply provide it. Plain pyegeria's `PlainSupply` provides no readers. The key
  will be refused in a later release.

## Known

- Two specs are unrunnable and are now listed with words instead of failing when run:
  `Asset-Graph` (`ServerClient.get_asset_graph` does not exist) and `Data-Classes`
  (`DataDesigner.find_data_classes` does not exist). Both fail check 1.
