# pyegeria 6.2.28

<!-- Other 6.2.28 sections are added by other branches; keep this one self-contained. -->

## Search and get filters: universal, checked, documented

- **Every `find_*` / `get_*` takes the standard filters as keyword arguments.** Each public
  method that sends a request body to Egeria (509 of them, sync and async) accepts `**kwargs` and
  passes them to the shared request helper. Signatures are unchanged apart from that. Methods
  that previously could not filter now can — including `DataDesigner.find_all_data_structures`
  / `find_all_data_fields`, `RuntimeManager.get_platforms_by_name` / `get_servers_by_name` and
  the other runtime lookups, `CollectionManager.get_collection_hierarchy` / `get_member_list`,
  and the get-by-GUID family (`GetFilters` now reach `GetRequestBody`; before, a filter
  keyword on a get-by-GUID was silently dropped). For example:

  ```python
  client.find_data_value_specifications("*", metadata_element_subtypes=["DataClass"])
  ```

- **Filter names are checked.** An unknown name warns with `UnknownFilterWarning` (a
  `UserWarning`, also logged at WARNING), naming the bad key and listing the valid ones, and is
  left out of the request. The valid names come from the request-body model the call sends
  (`SearchStringRequestBody`, `FilterRequestBody`, `GetRequestBody`, ...). Report specs'
  `spec_params` go through the same check, so a typo in a spec warns too.
  **A future release will raise `TypeError` instead of warning** — fix any warnings now.
- **Typed filters (PEP 692).** `SearchFilters`, `ListFilters`, `GetFilters` and `FindFilters`
  (in `pyegeria.core.request_filters`) are `TypedDict`s with a description per field. Methods
  annotate `**kwargs: Unpack[...]` so editors complete the filter names. Methods that already
  name some filters as explicit parameters keep a plain `**kwargs` (PEP 692 forbids the overlap);
  their filters still pass through and are checked.
- **Docs:** [Search and get filters](../search-and-get-filters.md) — the full tables, which
  Egeria request body each maps to, and examples.

### Behaviour changes to check

- A filter keyword that was silently dropped before now reaches Egeria. In particular
  `classification_names` on a find is now sent as `includeOnlyClassifiedElements` (it already
  meant that on a by-name get), so the Dr.Egeria `*-DrE-*` report specs that pass
  `classification_names` (e.g. Campaign → `find_projects`) now return only elements carrying
  that classification instead of all of them.
- A filter given as `None` never overrides a method's own default.
- `MetadataExpert.find_metadata_elements` builds its default body from any `FindRequestBody`
  field given as a keyword (before: a fixed subset).
- Two built-in report-spec families pass a filter their method does not have, and now warn
  when run: `metadata_element_types` → `ExternalReferences.find_external_references`
  (12 `Cited-Document-*`, `External-Data-Source-*`... specs) and `classification` →
  `GlossaryManager.find_glossary_terms` (`Question-DrE-*`). Those filters were always
  ignored; the fix belongs in the Dr.Egeria compact specs.
