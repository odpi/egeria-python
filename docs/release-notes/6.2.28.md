# pyegeria 6.2.28

## Fixed

- **The two unrunnable built-in report specs run again.** `Asset-Graph` named
  `ServerClient.get_asset_graph`, which no longer exists; it now calls
  `AssetCatalog.get_asset_graph_by_guid`, and its required parameter is `guid` (was `asset_guid`; the
  `hey_egeria` asset graph command passes the new name).
  `Data-Classes` named `DataDesigner.find_data_classes`, which no longer exists; it now calls
  `DataDesigner.find_data_value_specifications` restricted to the `DataClass` subtype
  (`metadata_element_subtypes=["DataClass"]`). The load-time census is now 437 specs: 376 runnable,
  61 format-only, none unrunnable (6.2.27: 374 runnable, 2 unrunnable).
- **`Asset-Graph` gives each output format a shape that fits a graph.** DICT and TABLE are an
  edge table: one row per edge, with the from element (display name, type, GUID), the relationship
  type, and the to element. It includes the asset's own relationships, lists each relationship
  once, and is sorted, so the order is deterministic. LIST is the nodes. REPORT and MD are the
  asset summary, its graph(s) as mermaid and the edge table; HTML renders that. MERMAID is the
  graph. JSON is the full graph response. No format returns one row of mermaid text. A by-GUID
  REPORT no longer says "found from the search string". FORM and ALL are not declared; asking
  for them is an error that names the declared formats. The anchor graph's misspelt column key
  (`anchorMermaidGRaph`) is corrected.
- **HTML output renders markdown tables.** The HTML renderer had GFM tables switched off, so a
  markdown table in a REPORT came out as text; it is now a table.
- **`exec_report_spec` no longer returns `None` when a find method raises `ValueError`.** It logs
  the error and raises it, so the caller sees the words.
