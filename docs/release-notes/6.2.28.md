# pyegeria 6.2.28

## Fixed

- **The two unrunnable built-in report specs run again.** `Asset-Graph` named
  `ServerClient.get_asset_graph`, which no longer exists; it now calls
  `AssetCatalog.get_asset_graph_by_guid`, and its required parameter is `guid` (was `asset_guid`; the
  `hey_egeria` asset graph command passes the new name).
  `Data-Classes` named `DataDesigner.find_data_classes`, which no longer exists; it now calls
  `DataDesigner.find_data_value_specifications` restricted to the `DataClass` subtype
  (`metadata_element_subtypes=["DataClass"]`). The load-time census is now 437 specs: 376 runnable,
  61 format-only, none unrunnable (6.2.27: 374 runnable, 2 unrunnable).
- **`Asset-Graph` renders the graph in every format it declares.** It declares DICT, TABLE and
  JSON (the asset's own fields plus its graphs as text), REPORT and HTML (the asset's fields with
  the asset, anchor and action graphs rendered as mermaid), and MERMAID (the asset graph). Each
  returns one row or one document for the asset itself. The anchor graph's column key was
  misspelt (`anchorMermaidGRaph`), so the anchor graph was always empty; it is now
  `anchorMermaidGraph`, and an Action Graph column (`actionMermaidGraph`) is added. ALL, MD, FORM
  and LIST are no longer declared: MD and FORM are Dr.Egeria update forms, LIST is a markdown
  table that cannot show a graph, and ALL rendered only the asset's name. Asking for one of them
  is an error that names the formats the spec does declare.
- **`exec_report_spec` no longer returns `None` when a find method raises `ValueError`.** It logs
  the error and raises it, so the caller sees the words.
