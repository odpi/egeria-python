# pyegeria 6.2.33

pyegeria 6.2.33 completes the pyegeria half of report-spec consumer folders, phase 2 (#582). It applies to Egeria-held report specs only:
- A consumer folder's sync follows its sub-folders.
- A consumer index records which consumers use each report spec.
- A ReportSpec with a governance zone stays out of shared caches.

## New

- **Consumer-folder sync follows sub-folders.**
  `sync_report_specs(recursive=None, depth_cap=5, index_consumers=True)`:
  - **Default:** the sync follows the CollectionFolder members of a consumer folder
    (`ReportSpecFolder::Consumer::...`). Any other folder is read flat. On `pyegeria report-specs sync`,
    `--recursive` / `--no-recursive` override the default.
  - **Bounded:** each GUID is read once, so a cycle or a second path doesn't repeat a read. The walk stops
    5 levels below the named folder (`depth_cap`) and never follows a RootCollection or a sibling consumer
    folder.
  - **Reported:** a spec found in a sub-folder is recorded against the named folder. The report names
    `folders_read` and `depth_cap_reached`.
  - **Not read is not removed:** if the walk was capped or a sub-folder read failed, the folder's cached
    specs are kept.
- **The consumer index: which consumers use each spec.**
  `build_consumer_index`, `refresh_consumer_index` and `read_consumer_index` read the root once, taking
  names and labels only. The root is `PYEGERIA_REPORT_SPEC_ROOT`, default `RootCollection::ReportSpecs`.
  - **Result:** `{label: [consumer, ...]}`, plus each consumer folder with its own status.
  - **Cache:** the index is cached as `consumers.json` beside the spec manifest. It is reread only when
    the file's mtime changes.
  - **Absence is never "none":** an unreadable or missing root gives status "not read", with the reason.
    An unreadable or capped consumer folder makes the status "partial".
  - **Refresh:** a folder sync refreshes the index (`report.consumers` says whether the root was read). If
    the refresh fails, the sync still succeeds.

## Changed

- **A ReportSpec with a governance zone stays out of shared caches.** A shared cache's manifest is
  shared, as the Portal's is.
  - **Skipped:** a shared sync doesn't sync any ReportSpec that has a governance zone, until a public-only
    read is available. Zones are read from the 6.2 header key `elementHeader.zoneMembership` and from the
    legacy classifications list.
  - **Pruned:** a copy already in the cache is removed, and the report says why.
  - **Private caches:** a per-user cache still takes zoned specs.
  - **Consumer index:** zoned labels are left out, and a note says so.
- **A hidden or deleted sub-folder is gone.** When a sub-folder's member read is refused as not visible
  (OPEN-METADATA-SECURITY-403-020) or not found (404), its specs are pruned and the report says so. A
  genuine error, such as a timeout or a 5xx, keeps the cache as it was.
