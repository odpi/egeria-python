# pyegeria/view

Output formatting and the report-spec registry — turns raw Egeria elements
into MD/LIST/DICT/REPORT/MERMAID/chart output.

| File | Role |
|---|---|
| `base_report_formats.py` | Two dicts merged by `get_report_registry()`: `generated_format_sets` (auto-generated by `refresh_specs` — do not hand-edit) and `base_report_specs` (hand-maintained built-ins, e.g. `Referenceable` — `refresh_specs` never touches it). Also auto-loads a CONFIG tier from `pyegeria.report_specs` entry points and the user report specs directory; code that isn't an installed package uses `register_report_specs()`. `PYEGERIA_REPORT_SPEC_MODULES` and config.json's list were removed in 6.2.19 (ISSUE-173). |
| `_output_format_models.py` | Pydantic models `Column`/`Format`/`FormatSet`/`ActionParameter` — define new report specs with these, not raw dicts. |
| `output_formatter.py` | `generate_output()` — materializes elements into MD/LIST/DICT/REPORT formats. |
| `format_set_executor.py` | `exec_report_spec()` — runs a `FormatSet`'s query/render path; dispatches `SERIES`/`BAR`/`PIE` output formats to Vega-Lite chart rendering before normal Format-row lookup. |
| `analytic_registry.py` / `analytic_demo_specs.py` | `analytic_registry.py` is the registry of analytic routines (aggregated-result functions, as opposed to per-element query+format). Each entry is a routine declaration (`RoutineDeclaration`; `AnalyticFunctionSpec` is its compatibility view): `inputs` by role, `params` with a `category`, `bindings` (the python binding is `function`, and a module allow-list applies to it only; a report spec names routines by registered name, never by path, ISSUE-173), `declaration` (results, `out`), `tile_safe`, `admission`. `analytic_demo_specs.py` holds one real, executable demo `FormatSet` per registered function. |
| `role_supply.py` | `RoleSupply` protocol and `PlainSupply`: how the executor obtains a routine's declared inputs (`egeria_client:<Class>`, `reader:<name>`, `viewer`, `subject`). Plain pyegeria supplies the caller's `EgeriaTech` only. `RoleRefused`, `NoSuchReader`, `CallerTokenExpired`. |
| `spec_resolver.py` | Load-time resolution of report specs: `resolve`, `unrunnable_specs`, checks 1-7, `declared_inputs` (check 5, shared with the executor). Backs `list_report_specs(with_status=True)`. |
| `overview_metrics.py` | ~25 dashboard-style analytic functions (counts, coverage %, leaderboards) built on `FindRequestBody` queries. |
| `_output_dashboard_sheet_models.py` | `DashboardSheet`/`Placement` — user-authored dashboard model, built via Dr.Egeria's Dashboard Sheet commands. |
| `mermaid_utilities.py` | Mermaid diagram generation helpers. |
| `vega_utilities.py` | Vega-Lite chart JSON generation helpers. |
| `dashboard_sheet_registry.py` | Registry of dashboard sheet definitions. |
| `dr_egeria_reports.py` | Large generated/legacy report-rendering module. |
| `md_processing_utils.py` | Small formatting helpers shared with `md_processing/`. |

Generated report specs follow `{Type}-DrE-{Basic|Advanced}` naming; see
`CLAUDE.md`'s "pyegeria SDK" section for the fuller architecture
description and the `refresh_specs`/`gen_md_cmd_templates` CLI tools that
regenerate content here.
