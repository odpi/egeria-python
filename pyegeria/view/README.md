# pyegeria/view

Output formatting and the report-spec registry — turns raw Egeria elements
into MD/LIST/DICT/REPORT/MERMAID/chart output.

| File | Role |
|---|---|
| `base_report_formats.py` | Two dicts merged by `get_report_registry()`: `generated_format_sets` (auto-generated by `refresh_specs` — do not hand-edit) and `base_report_specs` (hand-maintained built-ins, e.g. `Referenceable` — `refresh_specs` never touches it). Since RS-EGERIA-TIER stage 2 these (with the analytic demos and the question specs) are only the input of the seed generator; the registry's builtin tier loads from `seed/`. Also auto-loads a CONFIG tier from `pyegeria.report_specs` entry points and the user report specs directory; code that isn't an installed package uses `register_report_specs()`. `PYEGERIA_REPORT_SPEC_MODULES` and config.json's list were removed in 6.2.19 (ISSUE-173). |
| `seed/` | The report-spec seed (RS-EGERIA-TIER stage 2): pyegeria's shipped specs as packaged JSON, one file per family plus `manifest.json` (format, files, label order, census). `get_report_registry()` loads the builtin tier from it through `seed_report_specs()`. Each entry is `{label, envelope, microflow}` (microflow/1). Generated from the Python constants by `python -m pyegeria.view.seed build` (run by `refresh_specs`); `... seed check` fails when it is stale (a micro-test runs it). Do not hand-edit. `BOOTSTRAP_CORE` names the specs that always come from it. |
| `microflow.py` | `microflow/1`: the stored micro-flow model, its JSON Schema (`schemas/microflow-1.json`), the conversions to and from `FormatSet`, and the allowlists (`FIND_METHOD_ALLOWLIST`, `ADDITIONAL_PROPS_HOOKS`). |
| `_output_format_models.py` | Pydantic models `Column`/`Format`/`FormatSet`/`ActionParameter` — define new report specs with these, not raw dicts. |
| `output_formatter.py` | `generate_output()` — materializes elements into MD/LIST/DICT/REPORT formats. |
| `format_set_executor.py` | `exec_report_spec()` — runs a `FormatSet`'s query/render path; dispatches `SERIES`/`BAR`/`PIE` output formats to Vega-Lite chart rendering before normal Format-row lookup; runs a DOCUMENT spec's exporter and validator (SD-1). |
| `document_validators.py` | DOCUMENT validators by name: built-ins `json-schema`, `shacl`, `dcat-ap-3-shacl`; never fetch over the network; a spec may name only `package:` files. |
| `export_dcat.py` | `export_dcat` analytic function: a DCAT-AP 3 catalog (JSON-LD/Turtle) of the Assets in a collection or search, read as the caller (SD-2). Shapes vendored in `data/dcat-ap-3/`. |
| `analytic_registry.py` / `analytic_demo_specs.py` | `analytic_registry.py` is the registry of analytic routines (aggregated-result functions, as opposed to per-element query+format). Each entry is a routine declaration (`RoutineDeclaration`; `AnalyticFunctionSpec` is its compatibility view): `inputs` by role, `params` with a `category`, `bindings` (the python binding is `function`, and a module allow-list applies to it only; a report spec names routines by registered name, never by path, ISSUE-173), `declaration` (results, `out`), `tile_safe`, `admission`. `analytic_demo_specs.py` holds one real, executable demo `FormatSet` per registered function. |
| `role_supply.py` | `RoleSupply` protocol and `PlainSupply`: how the executor obtains a routine's declared inputs (`egeria_client:<Class>`, `reader:<name>`, `viewer`, `subject`). Plain pyegeria supplies the caller's `EgeriaTech` only. `RoleRefused`, `NoSuchReader`, `CallerTokenExpired`. |
| `spec_resolver.py` | Load-time resolution of report specs: `resolve`, `unrunnable_specs`, checks 1-7, `declared_inputs` (check 5, shared with the executor). Backs `list_report_specs(with_status=True)`. |
| `overview_metrics.py` | ~25 dashboard-style analytic functions (counts, coverage %, leaderboards) built on `FindRequestBody` queries. |
| `_output_dashboard_sheet_models.py` | `DashboardSheet`/`Placement` — user-authored dashboard model, built via Dr.Egeria's Dashboard Sheet commands. |
| `mermaid_utilities.py` | Mermaid diagram generation helpers. |
| `vega_utilities.py` | Vega-Lite chart JSON generation helpers. |
| `dashboard_sheet_registry.py` | Registry of dashboard sheet definitions. |
| `dr_egeria_reports.py` | The generated Dr.Egeria report specs as Python code (`FormatSetDict`), written by `refresh_specs` from the compact command specs; the same sets as `md_processing/data/generated_format_sets.json`. Not imported by pyegeria itself. |
| `md_processing_utils.py` | Small formatting helpers shared with `md_processing/`. |

Generated report specs follow `{Type}-DrE-{Basic|Advanced}` naming; see
`CLAUDE.md`'s "pyegeria SDK" section for the fuller architecture
description and the `refresh_specs`/`gen_md_cmd_templates` CLI tools that
regenerate content here.
